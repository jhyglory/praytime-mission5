작성일: 2026-11-06

이 문서는 승인받은 정정안의 이력이다. 기존 Privacy URL 게시 및 본문 확인을 완료했다. 법적 적정성 검토와 사용자 게시 승인은 구분한다. 아래 초안 작성 시점의 OFF/미게시 설명은 역사적 기록이다.

사용자가 승인한 작업은 정정안 작성과 검토 요청이다. 이 문서는 현재 게시된 고지를 대체하지 않는다. 실제 저장 활성화, 환경변수 변경, DB INSERT 및 배포는 이번 초안 작성에서 수행하지 않았다. `PRIVACY_COLLECTION_APPROVED=false`와 저장 OFF 상태를 유지한다.

대상 URL: https://praytime.glorifier.kr/privacy

## 게시 검토용 본문

### 개인정보처리방침

#### 1. 수집 항목

- 필수 입력 항목: 이름(닉네임), 이메일 주소, 사용 기기, 신청 이유.
- 선택 입력 항목: 연령대, 줄이고 싶은 앱, 최근 3개월 동안 SNS·스마트폰 사용을 줄이기 위해 시도한 방법.
- 유입 및 신청 경로 정보: UTM, referrer, 신청 페이지 식별 정보.
- 접수 시 생성되는 정보: 신청 식별값과 신청 시각. Mission 5 신청 페이지에서는 개인정보 수집·이용 동의 시각과 동의한 개인정보처리방침 버전도 기록합니다.

#### 2. 이용 목적

베타 초대와 출시 안내, 서비스 개선을 위한 통계 분석에만 사용합니다. 광고 목적의 제3자 제공은 하지 않습니다.

#### 3. 보관 및 파기

정식 출시 후 1년 또는 삭제 요청 시까지 보관하며, 목적 달성 후 지체 없이 파기합니다.

#### 4. 이용자 권리

언제든지 열람·정정·삭제 및 수신 거부를 요청하실 수 있습니다. 요청은 praytime.kr@gmail.com으로 보내주세요.

#### 5. 동의 거부와 신청

개인정보 수집·이용에 대한 동의를 거부하실 수 있습니다. 필수 정보 제공 및 수집·이용 동의가 없으면 베타 사전신청을 접수할 수 없습니다. 선택 입력 항목은 제공하지 않아도 신청할 수 있습니다.

## 게시 승인 전 확인할 사항

- 서비스 운영자가 2~4절의 기존 이용 목적·보관 기간·문의처를 현재도 그대로 운영하는지 확인한다. 특히 동의 기록의 이용 목적과 보관 기간이 기존 설명으로 충분한지는 **LEGAL REVIEW REQUIRED**다. 임의로 새 목적이나 보관 기간을 정하지 않았다.
- 실제 운영 서비스의 처리위탁·국외 이전·개인정보 보호책임자 등 추가 고지 필요 사항은 이 수집 항목 정합성 검토만으로 확인할 수 없다. 확인되지 않은 업체명·이전 국가·시행일을 만들지 않았다.
- 기존 Lovable 폼에는 Mission 5의 동의 시각·버전 기록 로직이 없다. 위 본문은 그 기록을 Mission 5 신청 페이지로 한정한다. 과거 신청자의 동의를 소급해 기록하거나 기존 행을 갱신하지 않는다.
- 선택 항목 입력과 별도 선택 동의의 구분이 필요한지는 검토가 필요하다. 현재 폼은 단일 필수 동의 체크박스를 사용하며, 이번 문서 작업에서 폼을 변경하지 않았다.

## 구현 대조표 — 게시 본문이 아닌 개발 참고

| 고지 항목 | 실제 필드 / 처리 |
| --- | --- |
| 이름(닉네임) | `nickname` |
| 이메일 | `email`, 소문자 정규화, 기존 UNIQUE 제약 유지 |
| 사용 기기 | `os` |
| 신청 이유 | `signup_reason`, 선택값을 문자열로 저장 |
| 연령대 | `age_range`, 미입력 시 null |
| 줄이고 싶은 앱 | `target_apps`, 미입력 시 빈 배열 |
| 최근 사용 감소 시도 | `reduction_methods`, 미입력 시 빈 배열 |
| 유입 정보 | `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `referrer` |
| 신청 경로 | `signup_source=mission5_landing` |
| 동의 기록 | 서버의 `privacy_consent_at`, 게시 확정본의 `privacy_policy_version` |
| 접수 정보 | DB가 생성하는 `id`, `created_at` |

동의 체크박스는 서버에서 true를 검증한다. 초안의 해시를 현재 정책 버전으로 등록하지 않는다. 승인 및 게시 후 실제 게시 본문을 기준으로 snapshot·version·검증을 갱신한다.

## 승인 후 진행 순서

1. 승인된 본문을 기존 Privacy URL에 게시하고 실제 공개 내용을 확인한다. 별도 Terms URL 및 DNS 전환은 만들지 않는다.
2. 게시된 고지 snapshot과 정책 version을 갱신한다.
3. 기존 Supabase INSERT 전용 연결을 Vercel 서버 환경에 설정하고 privacy guard를 승인 상태로 전환한다. 서비스 역할 키, 새 DB, RLS 변경은 사용하지 않는다.
4. lint·typecheck·unit·browser·production build를 검증한 뒤 기존 feature branch / PR #1 / Vercel 경로로 반영한다. merge하지 않는다.
5. 명확한 QA 데이터 1건으로 실제 INSERT와 동의 기록을 검증하고, 중복 요청·잘못된 요청 처리를 확인한다. 기존 사용자 데이터는 조회·수정하지 않는다. INSERT-only RLS 상태에서 저장값 확인이 불가능하면 성공 응답과 DB 필드 검증을 구분해 보고한다.
